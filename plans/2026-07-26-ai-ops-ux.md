# HOOKLAB: AI ops UX — timer, thinking toggle, timeouts, persistent error

## Goal
Stack-wide retrofit (2 of 4, after BLAST): elapsed timer + learned "typically
~Ns" on the AI underwrite, a thinking toggle (default ON), request timeouts so
a hung connection can't freeze the button, and a persistent error line.

## Facts
- One AI call site: underwriteWithAI (app.js ~598) — currently omits onPhase
  (llm.js retryReporter is dead code here) and sends NO thinkingConfig at all,
  so Gemini already does dynamic thinking against maxTokens 4096 (silent
  truncation risk). No fetch timeout anywhere in llm.js.
- Settings save is a merge (safe), but the pref uses the own-key + shared
  StackData pattern for stack consistency.

## Changes
- **llm.js**: same diff as blast — fetchWithTimeout (GEN 180s / UPLOAD_START
  30s / UPLOAD 15min / POLL 15s) wrapping all AI-path fetches; thinking opts
  (opts.thinking / opts.thinkingBudget, default budget 0) in both
  generationConfig builders; geminiFileResourceUrl poll fix for parity.
- **app.js**: `hooklab_ai_ms_v1` duration store + `hooklab_thinking_v1` +
  shared `aiThinking` (shared wins, default on, persisted on radio change);
  `aiRun` helper; underwriteWithAI threads onPhase and sends
  `thinkingBudget: on?2048:0, maxTokens: on?8192:4096` (thinking tokens count
  against the cap — raised headroom when ON); runGenerate AI branch wraps via
  aiRun("underwrite", #genLabel, #genError, "Underwriting with evidence", …).
- **index.html**: #genError after the button row; thinking radio row in the
  settings modal after the provider block.
- **style.css**: .ai-error rules.

## Rollback

(budget 0 + 4096) is the new fast path; ON restores today's dynamic thinking
with MORE output headroom than today.
